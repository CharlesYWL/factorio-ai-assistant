# Factorio AI Assistant v0.1.0-rc.7

本轮的主题是**让顾问看得见工厂、也能指着工厂说话**。Companion 改为持有全部配方数据、
只把目录发给模型（上下文降 67%），省下的预算用来承载框选详情与新增的矿脉数据；模型
则获得在游戏世界和地图上画标注的能力。Mod 与 Companion 必须来自同一 rc.7 bundle 成对安装。

> **Steam 成就警告：** Factorio 启用任何 Mod 后，该存档都不能获得 Steam 成就。请先备份存档
> 并使用测试副本。

本 RC 仅用于私有 GitHub Release 和 Windows 实机验收，不发布到 Factorio Mod Portal。

## 变更

### 新增：世界与地图标注

模型识别出问题机器或建议位置时，会调用 `highlight_entities`，Mod 在游戏里画出彩色方框
加文字标签，并同步创建一个**地图标签**（chart tag）——后者让被标记的位置在打开地图时
也能一眼找到，而不只是站在旁边才看得见。

- 标注有两种目标：**`unit`**（已有机器）会与当前选区比对，模型编造的编号会被拒绝并告知，
  不会产生指向空无一物的标注；**`x`/`y`**（地图坐标）无从校验，按原样接受——这是
  「建议在这里开矿」「这里该加个泵」能被表达出来的前提，因为空地上没有实体可引用。
- 标注**不会自动消失**，保留到手动清除或下一次回答产生新标注。定时消失的问题是玩家
  走过去的路上它就没了。
- 清除方式：`Ctrl+Shift+C`，或聊天页「清空」旁边的**清除标注**按钮。清除会同时删掉
  世界标注和地图标签。
- 上限 12 个标注、每个 60 字；后一次调用替换前一次。

### 新增：连接关系与实体身份

框选采集补上了三样此前完全缺失的数据：

- **`unit`**（`unit_number`）：稳定编号，既是标注锚点，也让实体之间能互相引用。
- **`facing`**：朝向名，判断流向的前提。
- **`link`**：**机械臂现在纳入详细采集**，带 `pickup_target` / `drop_target`。

`link` 是关键补充。此前模型只能说「这台停了」，现在能看到「A 号机械臂从 B 取料、给 C」，
断料链条第一次可追溯。

### 新增：矿脉采集

新增 `resource_snapshot`，给模型第一份「地图」。已探索区域的矿脉按 chunk 聚合、相邻同种
矿洪水填充合并成一片，给出中心坐标、剩余储量和覆盖格数。

扫描跑在游戏主线程上，所以刻意做了限制：只走已探索的 chunk（上限 2048），每**两游戏
分钟**才刷新一次（矿不会跑），按储量排序只留最大的 40 片。

### 变更：Companion 持有上下文，模型按需索取

此前每次请求都把整个配方目录（含原料）塞进 prompt。实测 200 配方的存档，光配方就要
**31.6 KB，占掉整个预算的 87%**，真正反映工厂现状的实时产销只剩 4%。

现在配方数据留在 Companion，只把目录（ID + 游戏内显示名）发给模型，需要原料时它自己
调工具取：

| | 字节 |
| --- | ---: |
| 旧：完整配方块 | 21,912 |
| 新：目录（ID + 名称） | 4,840 |
| 新：`get_recipe` 取 5 条 | 545 |
| **节省** | **75.4%** |

实测单次请求上下文从 36,353 B 降到 11,999 B（**降 67%**）。省下的预算给了框选数据：
现在框 205 台机器（29 KB）仍然一台都不裁剪。

目录必须**完整**发送而不能按问题裁剪：玩家说「黄瓶」时，这个词在存档里叫「银金分析包」，
按名字匹配会一条都命中不了。模型看得见完整目录才能自己完成映射。

新增只读工具：

| 工具 | 输入边界 | 输出 |
| --- | --- | --- |
| `get_recipe` | 最多 16 个配方 ID | 原料、产物、制作秒数与显示名 |
| `search_recipes` | 至少 2 字符 | 最多 12 条 ID / 名称匹配 |
| `highlight_entities` | 最多 12 个标注 | 世界方框、文字标签与地图标签 |

工具轮次上限为 3，超出后去掉工具再问一次，强制模型用已取到的数据作答。

### 变更：回答到达时的界面行为

一次提问可能要等一两分钟，玩家很可能已经关掉面板走开了。

- 面板开着：滚到最新一行。
- 面板关着：**自动以迷你模式打开**，切出迷你模式时恢复原本尺寸。
- `/ai` 提问除外：那个玩家主动选择了不开面板，答案已在聊天区。

自动打开**不触发自动暂停**。暂停的语义是「玩家打开面板去思考」，而这次是面板自己弹出来
的——因为一条回答恰好到了就冻结游戏，会打断玩家正在做的事。

## 修复

- **定时提醒长时间消失**：dev watcher 重启 Companion 时撞上 `EADDRINUSE` 后静默放弃，
  导致没有任何进程监听 34197，游戏发出的包被全部丢弃，而游戏侧毫无报错。现在启动时会
  清理孤儿进程、端口冲突按 0.5s→15s 递增重试，彻底失败时打印醒目告警。
- **界面在答案返回前就超时**：Mod 侧等待上限 40 秒是加工具调用**之前**定的。一次 48.5 秒
  的请求明明成功产出了答案和 10 个标注，界面却已经报超时。现在四层超时严格递增
  （单次 HTTP 60s → 单趟往返 90s → 工具循环 120s → Mod 等待 240s），最坏情况 210s，
  留 30s 余量。
- **`unit` 等字段在最后一步被丢弃**：Mod 采集了、协议解码了，但 `compactSelection()` 组装
  发给模型的数据时从未复制 `unit`/`facing`/`link`。模型明确反馈「实体没带 unit 编号」，
  是准确的。已补测试锁住这个契约。

## 存档兼容

- rc.6 存档可直接升级，不需要迁移步骤。
- 新增的 `state.highlights`、`state.highlight_tags`、`state.last_resource_tick` 均为可选，
  旧存档缺少时按默认值处理。
- 聊天历史、已忽略提醒与自动暂停 claim 均不受影响。

## 协议兼容

协议版本仍为 `1`，状态 schema 仍为 `2`。本轮新增字段与包类型全部是**可选或新增**：

- `area_snapshot.payload.entities[].unit` / `facing` / `link`：可选，旧版 Mod 不发送。
- `highlight`：新增包类型（Companion → Mod）。
- `resource_snapshot`：新增包类型（Mod → Companion）。

混装行为：

- rc.6 Companion + rc.7 Mod：矿脉包被拒绝，标注不会下发，框选的新字段被忽略。
- rc.7 Companion + rc.6 Mod：不发送矿脉与新字段，标注下发后旧 Mod 按未知类型丢弃。
- 仍然要求成对安装同一 bundle。

## 实机验收清单

- **框选诊断**：框选一片有停机的区域，问「这里为什么有机器不进料」。回答应引用真实
  `status`，并在世界与地图上标出问题机器。
- **坐标标注**：不框选，问「我该去哪开矿」。回答应给出具体矿脉并在地图上标出位置。
- **清除标注**：`Ctrl+Shift+C` 与聊天页按钮都应清掉世界标注与地图标签。
- **自动弹窗**：提问后关闭面板，等回答返回，面板应自动以迷你模式弹出且**游戏不被暂停**。
- **长等待**：需要多轮工具调用的复杂问题不应再在界面上报超时。
- **矿脉扫描耗时**：`factorio-current.log` 的 `Resource scan` 行应显示可接受的耗时。

## 已知限制

- 移除模型输出校验后，回答的算术正确性由模型负责。确定性数据仍然全部来自存档，但模型的
  推导本身不再被本地规则复核。
- 框选采集的是**松手那一刻的快照**，工厂持续运行，稍后再问时状态可能已变化。
- 选区与标注不持久化到 Companion：Companion 重启后需要重新框选。
- 矿脉只覆盖**已探索**区域，且每两游戏分钟才刷新一次。
- 除机械臂外仍不采集连接关系：传送带、管道的拓扑对模型不可见。
- 自动暂停**只支持单人游戏**。
- 像素布局、键盘焦点、不同 UI scale 与 DPI，以及真实 Lua/UI UPS 仍需 Windows 实机确认。
