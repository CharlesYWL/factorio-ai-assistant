# Factorio AI Assistant v0.1.0-rc.2

第二个私有 release candidate。它在 rc.1 的只读基线上合入 Windows 实机 hotfix、游戏内
可用性修复、中文显示名称、内置 Factorio 2.0 原版流程指南，并把生产比例计算从独立表单
改为聊天自动调用。Mod 与 Companion 仍必须成对安装。

> **Steam 成就警告：** Factorio 只要启用任何 Mod，该存档就不能获得 Steam 成就。
> 请先备份存档，并用专门的测试副本验收。

本 RC 仅用于私有 GitHub Release 和 Windows 实机验收，**不会自动发布到 Factorio
Mod Portal**。

## 相对 rc.1 的变化

### 聊天与面板可用性
- 新消息、发送、完成和超时后聊天区自动贴回底部；玩家向上翻看历史时，其它刷新
  （例如新告警到达）不会把视图抢回底部。
- 聊天区新增**清空**按钮，只清除本机聊天历史与 pending UI；进行中的请求被安全取消，
  Companion 连接与提醒不受影响。
- 新增左上角**常驻提醒卡片**：待办式列表，只在有活动告警时出现，显示严重度、规则标题
  和证据摘要，并提供“打开顾问”与逐条忽略。忽略只作用于当前告警生命周期，告警关闭后
  再次触发会重新出现；规则静音仍是独立开关。Alerts 页同样可忽略 / 恢复。
- 低打扰 toast 保留，但常驻卡片是主要的可回看入口。

### 中文显示名称
- 产品、流体、科技、配方和机器按当前游戏语言显示（例如 `铁板` 而不是 `iron-plate`）。
- 名称来自 Factorio 官方翻译机制，只翻译实际会展示的 ID，不在启动时全量翻译。
- prototype ID 仍是协议主键，保留在 tooltip 与结构化输出中；未翻译或未知 ID 安全回退
  为 ID 本身，中英切换后不会残留上一语言的名称。
- 覆盖 Chat 的事实 / 模型上下文、Alerts 证据与建议、聊天触发的计算结果与状态页。

### 内置原版流程指南
- 新增 `packages/guide`：版本化的 Factorio 2.0 base 流程指南（guide 1.0.0，对照
  Factorio 2.0.72 校订）与确定性阶段判定引擎。
- 问“下一步做什么 / 该扩建什么 / 该研究什么”时，按当前已研究科技、可用配方、当前科研和
  净流量判定阶段，给出有顺序的步骤并引用 guide rule 与 `[A#]` / `[C#]` 证据；有活动告警时
  先修当前瓶颈。
- 指南是仓库内的静态数据，运行时不联网、不抓攻略，也不会把网页内容交给模型。资料来源与
  更新流程见 [`docs/guide.md`](../guide.md)。

### 聊天内确定性计算
- 移除需要手填 prototype ID 的 Calculator 页；面板固定为 Chat / Alerts / Status 三页。
- 直接用自然语言提问（“每分钟 45 个蓝瓶需要多少台机器”“一分钟 120 绿板怎么配”），
  Companion 用同步到的 catalog、游戏语言名称和常见中文别名解析出稳定 ID 与速率，
  再调用同一个确定性求解器返回配方、精确台数与向上取整台数。
- 目标、速率或替代配方不明确时返回一句简短澄清，而不是要求玩家输入内部 ID。
- 模型只能解释确定性结果，不能改写机器数、原料速率、带宽与假设。
- `packages/calculator` 与 JSON CLI（`npm run calculate`）保留；协议的 calculation
  request/response 保持兼容，混装旧版本不会崩溃。

### 打包与版本一致性
- Companion 的临时 hotfix 构建标记（`production-advice-hotfix-7`）收敛为正式 RC 标识，
  `companion_listening` 日志的 `build` 字段现在就是 release tag `v0.1.0-rc.2`。
- `check:release` 新增该标记与 release tag 的一致性断言，RC 标签、release notes 路径和
  CI 产物名统一从 `release.config.json` 派生，不再逐处硬编码 RC 序号。

## 资产

- `factorio-ai-assistant_0.1.0.zip`：直接放入 Factorio `mods` 目录的 Mod。
- `factorio-ai-assistant-companion-windows-x64-0.1.0.zip`：Node.js 22 Windows
  Companion、启动脚本、诊断脚本和示例配置。
- `companion.config.example.json`：无密钥的本地模式配置模板。
- `performance-baseline.json`：空闲、正常生产和接近 16 KiB 的大基地摘要自动基线。
- `SHA256SUMS`：上述文件的 SHA-256。
- `factorio-ai-assistant-v0.1.0-rc.2.zip`：包含全部资产、说明和校验值的总包；同目录
  `.sha256` 文件校验总包自身。

Factorio 的 Mod 版本格式不支持 prerelease 后缀，因此 Mod 内部版本为 `0.1.0`，
GitHub 候选标签为 `v0.1.0-rc.2`。协议版本 `1`、状态 schema 版本 `2` 与 rc.1 相同，
但 **rc.1 与 rc.2 的组件不要混装**：仍请成对替换。

### 可重复性边界

打包使用固定时间戳和固定条目顺序的确定性 ZIP：**Mod ZIP、Companion ZIP、示例配置、
`manifest.json` 和 `RELEASE_NOTES.md` 在同一提交上重复执行 `npm run package` 会得到完全
相同的 SHA-256**（本轮已双跑比对确认）。

`performance-baseline.json` 是每次构建实测的性能报告，其中的耗时和运行时信息按机器与
负载变化，因此它本身以及包含它的总 bundle `factorio-ai-assistant-v0.1.0-rc.2.zip` 的
SHA-256 是**每次构建一份**，不跨构建重现。验收时以本 Release 内 `SHA256SUMS` 和
`.sha256` 附件为准：它们与本次上传的资产一一对应。

## 安装与升级

按 [`docs/setup-windows.md`](../setup-windows.md) 安装，并按
[`docs/windows-smoke-test.md`](../windows-smoke-test.md) 完成 25–40 分钟统一冒烟测试。

Mod 和 Companion 必须来自同一个 release bundle。从 rc.1 升级时先退出 Factorio 和
Companion，删除旧 Mod ZIP 与旧 Companion 目录，再同时装入 rc.2 两者；保留自己的
`companion.config.json`。如果版本或协议不匹配，游戏内状态页会显示双方版本并停止聊天、
计算和新状态同步，不会在不兼容数据上继续运行。

## Windows 实机统一验收清单

完整步骤见 [`docs/windows-smoke-test.md`](../windows-smoke-test.md)。本轮必须覆盖：

- [ ] 两个 ZIP 的 SHA-256 与 `SHA256SUMS` 一致，且都来自 `v0.1.0-rc.2` bundle。
- [ ] 连接与状态：Status 显示 Connected、Mod `0.1.0`、Companion `0.1.0`、协议 `1 / 2`。
- [ ] 聊天与降级：回答区分事实 / 推断 / 缺失数据；断开 provider 后 35 秒内本地降级。
- [ ] 聊天内确定性计算：蓝瓶 / 绿板 / 钢材 / 塑料 / 硫磺 / 电池六问全部返回结构化结果，
      全程不输入任何 prototype ID；“电路”与缺速率的问题返回澄清。
- [ ] 中文显示名称：zh-CN 下正文用中文名，英文语言下用英文名，未翻译 ID 安全回退。
- [ ] 流程指南：“下一步做什么 / 该扩建什么 / 该研究什么”给出有顺序、有证据的步骤，
      有活动告警时优先当前瓶颈。
- [ ] 提醒与防风暴：同一告警不按每 5 秒样本重复弹出；静音与恢复有效。
- [ ] 聊天滚动 / 清空 / 常驻提醒：`chat-long`、`chat-append`、`chat-cleared`、
      `alerts-none / one / many`、`alert-close` / `alert-reopen` 全部符合预期。
- [ ] 断网降级与恢复：关闭 Companion 后约 10 秒转 Offline，重启后约 5 秒恢复同步。
- [ ] 100% / 150% UI scale 与纯键盘操作下按钮可访问、不重叠、不遮挡快捷栏与小地图。
- [ ] `collect-diagnostics.ps1` 生成的诊断包不含密钥或状态全文。

## 已知限制与实机待验

- 当前自动环境没有 Factorio；Windows + Steam 图形界面、DPI、键盘焦点、防火墙和
  真实 Lua UDP 仍需实机确认。
- 真实存档的空闲、正常生产、大基地摘要三场景 UPS，以及连续运行 30 分钟无未处理异常，
  需按 [`docs/performance.md`](../performance.md) 记录。
- 聊天计算自动选择上游配方与机器；同一资源的多配方歧义会返回澄清而不是猜测，需要显式
  指定机器 / 插件 / 替代配方时仍使用 JSON CLI。
- 流程指南只覆盖 Factorio 2.0 base 到首发火箭；不含 Space Age，也不知道地图布局、库存、
  皮带与单机状态，只按聚合数据和已研究科技推断阶段。
- 中文名称依赖 Factorio 的翻译事件，连接后需要约 5–10 秒填充；填充完成前会先显示 ID。
- 模型请求取消只保证终止仍在执行的请求；已经进入 UDP 的响应可能先到达。
- Provider 故障会在 30 秒总预算内降级到确定性本地结果，但不会离线修改工厂。

在上述 Windows 实机项目全部通过前，本候选与 MYW-105 保持待评审状态。
