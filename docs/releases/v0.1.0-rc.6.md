# Factorio AI Assistant v0.1.0-rc.6

第六个私有 release candidate。本轮是自 rc.1 以来改动最大的一次：**顾问不再用正则解析玩家的
提问，改为把本存档的真实配方交给模型推理**；同时新增框选提问、迷你面板与 `/ai` 命令，并修复
了两个会给出错误答案的缺陷。Mod 与 Companion 必须来自同一 rc.6 bundle 成对安装。

> **Steam 成就警告：** Factorio 启用任何 Mod 后，该存档都不能获得 Steam 成就。请先备份存档
> 并使用测试副本。

本 RC 仅用于私有 GitHub Release 和 Windows 实机验收，不发布到 Factorio Mod Portal。

## 相对 rc.5 的变化

### 新增：框选提问

右下角快捷栏新增 **AI 顾问检查器**。拖框选中一片区域后面板自动打开，可以直接就这片区域提问，
例如「为什么我满带铁矿带不动这些炉子」。

- 生产设备（熔炉、组装机、采矿机、实验室、化工厂、箱子、储罐、信标）**逐台**上报：坐标、
  配方、`entity.status`（缺料 / 输出堵塞 / 缺电）、插件、库存与流体。`status` 是让「这台为什么
  停了」第一次变得可答的关键字段。
- 传送带、机械臂、电线杆等按类型计数，因为一次框选轻易包含数百个，逐台上报只会把真正被问到
  的设备挤出预算。
- 扫描只在玩家拖框时发生，范围限于选区，不遍历全图，也不在任何定时器上运行。
- 复用动态快照的分片契约，大选区不会被截断。
- 选区在上下文里的优先级仅次于配方；预算紧张时先舍弃库存明细，而不是丢掉设备本身。

按 Q 收起光标不会清除已发送的选区，选区保留到下次框选或 Companion 重启。

### 新增：迷你面板与 `/ai` 命令

- 标题栏新增切换按钮，进入迷你模式后只显示最近一条回答和输入框，方便边看工厂边提问；切回时
  恢复切换前的尺寸。
- `/ai <问题>` 把答案直接打印到游戏聊天区，适合不想打开面板的场景。Factorio 内置聊天框是引擎
  UI，Mod 无法扩展，命令是唯一入口。
- 关闭面板时也会保存位置：调整尺寸可能移动窗口却不触发 location-changed 事件。

### 变更：由模型理解问题，而不是正则

Companion 过去会分类意图、解析速率、用硬编码别名表识别产物、切分句子找目标，最后还要求模型
回答里的每个数字都逐字出现在预先算好的证据里。每一层都在误判：

- 「10个蓝板要多少绿板和铜线」被当成红瓶问题，因为切句逻辑把真正的目标丢掉了；
- 正确答案因为做了玩家要求的算术而被判为数字冲突并丢弃。

这些层全部移除。模型真正无法知道的是**本存档的配方**——Mod 会改名和改配方，因此现在把该 force
能制作的完整配方目录以紧凑格式发给模型，由它自己推理。别名表在这里也注定失效：本测试存档把
utility science 改名为「银金分析包」，原料与原版完全不同。

配方按与问题的相关度排序，预算不足时优先保留被问到的产业链；紧凑编码使可容纳的配方数量大约
翻倍。提示词只保留安全约束：不输出 Lua / 控制台命令、不声称修改工厂、上下文按数据而非指令处理。

### 修复：装桶配方被当作生产路线

询问蓝电路会失败并报 `AMBIGUOUS_RECIPE`，因为有两条配方能产出硫酸：真正的生产配方和
`empty-sulfuric-acid-barrel`。倒空桶只是把已经装桶的硫酸放出来，永远无法创造新供给，不应与真
路线竞争。

现在当某个候选配方的全部原料都只能由「消耗目标物本身」的配方产出时，它会被跳过。该过滤只用于
破除歧义，已经唯一确定的目标不受影响，既有配比结果不变。

同时修正了误导性文案：数据完整、只是路线未定时，过去会声称「同步数据不足」。现在会说明是路线
有多种选择，并列出候选配方——不给出选项的「告诉我走哪条路线」是无法回答的。

### 修复：动态快照不再丢弃生产数据

繁忙基地的产物流量超过单个 16 KiB datagram，导致每次采样静默丢弃约 30 条，关于当前产量的问题
因此基于不完整数据作答。现在样本会像静态快照一样续到下一个分片。

UDP 没有重传，因此**收不齐的样本整体丢弃**而不是部分发布：半个样本和被截断的样本一样会低报
产量，只是更不易察觉。

### 新增：可选的多轮追问

「那铜板呢」这类追问过去无法理解，因为每次请求都是独立的。玩家现在可以在 Mod 设置里开启
**追问时发送最近对话**，请求会附带他本人最近最多 4 轮问答。

- 默认关闭。
- 历史由 Mod 持有并随请求发送，Companion 不保存任何会话状态，因此同一势力中其他玩家的对话
  永远不会进入你的请求。
- 这是对隐私承诺的修订：此前文档声明聊天内容从不离开游戏，现已按实际行为更新
  （[`docs/companion.md`](../companion.md)、[`docs/protocol.md`](../protocol.md)）。

### 修复：Factorio Mod lint 在 Windows 检出上恒失败

`scripts/lint-factorio-mod.mjs` 用含裸 `\n` 的字符串字面量做断言，而 git 在 Windows 上以 CRLF
检出源文件，导致「Dynamic sampling and UI refresh must share the single 60-tick handler」一直
失败。现在读取时统一归一化换行，修复的是整个文件而不只是那条恰好跨行的断言。

### 新增：热重载开发流程

- `npm run dev`：增量编译并在保存后自动重启 Companion。
- `npm run dev:link` / `dev:unlink`：把工作区的 Mod 以目录联接挂进 Factorio，改 Lua 只需重新
  读档。
- `node scripts/dev-ask.mjs "<问题>"`：用真实 UDP 协议向运行中的 Companion 提问，本轮多个缺陷
  都是靠它在不进游戏点界面的情况下复现的。
- 流程说明见 [`docs/development.md`](../development.md)。

### 存档兼容

- rc.5 存档可直接升级，不需要迁移步骤。
- 新增的 `player_state.selection`、`size_before_mini` 均为可选字段，旧存档缺少它们时按默认值
  处理。
- 聊天历史、已忽略提醒与自动暂停 claim 均不受影响。

## 协议兼容

协议版本仍为 `1`，状态 schema 仍为 `2`。本轮新增的字段与包类型全部是**可选或新增**，不修改既有
字段语义：

- `assistant_request.payload.history`：可选，仅在玩家开启追问设置时出现。
- `dynamic_snapshot.payload.chunk_index` / `chunk_count`：可选，缺省表示单包样本，因此旧版 Mod
  仍然兼容。
- `area_snapshot`：新增包类型；旧版 Companion 会按未知类型拒绝，不影响其他功能。

混装行为：

- rc.5 Companion + rc.6 Mod：框选包被拒绝，其余功能正常，但动态分片不会被重组，因此不要混装。
- rc.6 Companion + rc.5 Mod：不发送框选与分片包，功能退化为 rc.5 行为。
- 仍然要求成对安装同一 bundle。

- `factorio-ai-assistant-companion-windows-x64-0.1.0.zip`：Node.js 22 Windows Companion、
  启动脚本、诊断脚本和示例配置。
- `companion.config.example.json`：无密钥的本地模式配置模板。
- `performance-baseline.json`：空闲、正常生产和接近 16 KiB 大基地摘要的自动基线。
- `SHA256SUMS`：上述文件的 SHA-256。
- `factorio-ai-assistant-v0.1.0-rc.6.zip` 与同目录的 `.sha256`：总包及其自校验值。

Factorio 的 Mod 版本格式不支持 prerelease 后缀，因此 Mod 内部版本仍是 `0.1.0`，GitHub 候选
标签为 `v0.1.0-rc.6`，Companion build marker 同步为 `v0.1.0-rc.6`。**不要与 rc.1 ~ rc.5 或临时
hotfix 混装**，请成对替换。

### 可重复性边界

Mod ZIP、Companion ZIP、示例配置、`manifest.json` 和 `RELEASE_NOTES.md` 使用确定性打包，同一
提交上重复执行 `npm run package` 得到相同的 SHA-256。`performance-baseline.json` 是每次构建的
实测数据，因此它以及包含它的总 bundle 的 SHA-256 每次构建各不相同，验收时以本 Release 内的
`SHA256SUMS` 和 `.sha256` 附件为准。

  `check:security` 全部通过。Lua lint 本轮首次真正通过，此前因 CRLF 缺陷恒失败。
- 新增回归覆盖：装桶往返不参与选路、配方目录在预算不足时的裁剪顺序、动态与框选分片的重组 /
  乱序 / 丢包 / 旧样本混入、追问的默认关闭与跨玩家隔离、日志对话文本脱敏。

  总 bundle 全部通过。
- CI 覆盖 Ubuntu 与 Windows 构建测试、lint/release/security 门禁与 release packaging。

## Windows 重点复测

完整清单见 [`docs/windows-smoke-test.md`](../windows-smoke-test.md)，本轮重点：

- **框选提问**：快捷栏取出检查器，框选一片熔炉阵列，面板自动打开；提问后回答应引用选区内的
  真实设备状态（例如多少台 `no_ingredients`），而不是泛泛而谈。
- **迷你模式**：标题栏按钮切换后只显示最近一条回答与输入框；提问、等待、回答正常；再次点击
  恢复原尺寸；关闭再打开位置保持。
- **`/ai` 命令**：`/ai 现在电力够吗` 的答案出现在聊天区。
- **本存档配方**：询问被 Mod 改名的产物（如「黄瓶」），回答必须使用本存档的真实配方与名称，
  而不是原版配方。
- **动态数据完整性**：`factorio-current.log` 的 State sample 行 `omitted_series=0`，Companion
  日志不再出现 `dynamic_snapshot_truncated`。
- **追问**：开启「追问时发送最近对话」后连续追问；关闭时不发送历史。
- 既有回归：§4c 自动暂停语义、§4b 清理提醒、聊天贴底 / 清空、中文显示名称、provider 断网降级、
  Companion 关闭约 10 秒转 Offline 并可恢复。

## 已知限制与实机待验

- **传送带实际吞吐无法采集**。Factorio 只暴露带上的物品列表，不暴露单位时间通过量，因此涉及
  带子的问题只能按等级理论上限推算；分流与优先级导致的供给不均超出可采集范围。
- 框选采集的是**松手那一刻的快照**，工厂持续运行，稍后再问时状态可能已经变化。
- 选区不持久化：Companion 重启后需要重新框选。
- 移除输出校验后，回答的算术正确性由模型负责。确定性数据（配方、机器速度、产量统计）仍然全部
  来自存档，但模型的推导本身不再被本地规则复核。
- 自动暂停**只支持单人游戏**，多人游戏中该设置不生效（UI 会说明）。
- 顾问仍然只读，不自动建造 / 研究 / 执行 Lua 或 RCON；框选工具同样只读。
- 像素布局、键盘焦点、不同 UI scale 与 DPI，以及真实 Lua/UI UPS 仍需 Windows Factorio 实机
  确认。
- 本候选等待 Charles 的 Windows 实机验证，验收通过前不做 Mod Portal 发布。
