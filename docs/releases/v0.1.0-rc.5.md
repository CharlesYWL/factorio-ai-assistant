# Factorio AI Assistant v0.1.0-rc.5

第五个私有 release candidate。**本轮唯一的产品变化是撤回 rc.4 的“AI 建议加入待办”功能**：
该能力已从产品中移除，不会改成第三方 Todo-List 集成，也不保留内置待办。rc.4 的其余改进
（单人自动暂停、一键清理全部提醒）和 rc.3 的紧凑回答与本地化全部保留。Mod 与 Companion
必须来自同一 rc.5 bundle 成对安装。

> **Steam 成就警告：** Factorio 启用任何 Mod 后，该存档都不能获得 Steam 成就。请先备份存档
> 并使用测试副本。

本 RC 仅用于私有 GitHub Release 和 Windows 实机验收，不发布到 Factorio Mod Portal。

## 相对 rc.4 的变化

### 撤回：AI 建议 → 游戏内待办

以下能力全部移除，游戏里不再有任何待办概念：

- Chat 建议旁的 **加入待办 / 已加入** 按钮。
- Alerts 页内的待办区块，以及完成 / 恢复 / 删除 / 清理已完成 / 清理全部操作。
- 常驻提醒卡片上的未完成待办计数行。
- 存档中的待办持久化、去重、上限与相关 GUI handler。
- 面向玩家的待办 locale、README 段落、Windows 冒烟测试 §4c、UI 预览图与
  `/factorio-ai-assistant-mock todos` 模式。
- 协议里为采纳而新增的 `assistant_response.payload.suggested_actions` 字段、对应 fixtures，
  以及 Companion 侧的 `action_id` / `source` 生成与再净化链路。

**保留：AI 仍然会给出下一步建议。** 回答正文照旧以紧凑编号文本列出最多 3 条基于流程指南、
活动提醒或确定性计算的下一步——这正是采纳按钮出现之前的展示方式，只是不再可点击。

### 保留：rc.4 的其余能力

- 单人打开顾问时自动暂停（每玩家设置，默认开启），以及 Mod 只恢复自己那次暂停的 claim 语义。
- Alerts 页与常驻提醒卡片的 **清理全部**，逐条忽略 / 恢复、安静模式与规则静音均不受影响。
- rc.3 的紧凑回答、中文显示名称与本地化。

### 存档兼容

- rc.4 存档可以直接升级：载入时 `ui_state.ensure_player` 会安全丢弃 `player_state.todos`、
  `todo_sequence` 以及聊天记录上残留的 `suggested_actions`，不崩溃、不留下不可见的死数据。
- 迁移不触碰 `dismissed_alerts`、聊天历史与自动暂停 claim。
- 从未使用过待办的存档、以及 rc.4 之前的旧存档路径都不受影响。
- **本 Mod 从未读写任何第三方 Todo-List Mod 的数据，撤回同样不会触碰玩家实际安装的第三方
  Mod。** main 上也不含任何第三方 Todo-List 兼容或 remote 集成资产。

### 回归

- `scripts/lua/todos_spec.lua` 删除；`scripts/lua/integration_spec.lua` 改为覆盖剩余接缝：
  - 从常驻卡片或 Alerts 页清理全部提醒都不会释放自动暂停 claim；
  - Companion 回答经真实 UDP 路径抵达后，pending 清空、聊天历史增长，暂停 claim 不变；
  - `/factorio-ai-assistant-mock alerts-one` 只 claim 一次暂停，清理提醒后仍保持暂停；
  - 没有暂停 claim 的旧存档能安全迁移并继续正常暂停 / 恢复；
  - rc.4 存档丢弃待办数据后，聊天历史、已忽略提醒与提醒卡片全部完好。

## 协议兼容

协议版本仍为 `1`，状态 schema 仍为 `2`，没有为了撤回而变更版本号。`suggested_actions` 曾是
**可选**字段，因此移除它不构成破坏性变更：

- rc.4 Companion + rc.5 Mod：该字段被 rc.5 Mod 当作未知字段忽略，回答正文照常显示。
- rc.5 Companion + rc.4 Mod：回答不再带该字段，rc.4 Mod 走它原有的“无结构化建议”分支，
  只是不出现加入待办按钮。
- 仍然建议成对安装同一 bundle。

## 资产

- `factorio-ai-assistant_0.1.0.zip`：直接放入 Factorio `mods` 目录的 Mod。
- `factorio-ai-assistant-companion-windows-x64-0.1.0.zip`：Node.js 22 Windows Companion、
  启动脚本、诊断脚本和示例配置。
- `companion.config.example.json`：无密钥的本地模式配置模板。
- `performance-baseline.json`：空闲、正常生产和接近 16 KiB 大基地摘要的自动基线。
- `SHA256SUMS`：上述文件的 SHA-256。
- `factorio-ai-assistant-v0.1.0-rc.5.zip` 与同目录的 `.sha256`：总包及其自校验值。

Factorio 的 Mod 版本格式不支持 prerelease 后缀，因此 Mod 内部版本仍是 `0.1.0`，GitHub 候选
标签为 `v0.1.0-rc.5`，Companion build marker 同步为 `v0.1.0-rc.5`。**不要与 rc.1 / rc.2 /
rc.3 / rc.4 或临时 hotfix 混装**，请成对替换。

### 可重复性边界

Mod ZIP、Companion ZIP、示例配置、`manifest.json` 和 `RELEASE_NOTES.md` 使用确定性打包，同一
提交上重复执行 `npm run package` 得到相同的 SHA-256。`performance-baseline.json` 是每次构建的
实测数据，因此它以及包含它的总 bundle 的 SHA-256 每次构建各不相同，验收时以本 Release 内的
`SHA256SUMS` 和 `.sha256` 附件为准。

## Windows 重点复测

完整清单见 [`docs/windows-smoke-test.md`](../windows-smoke-test.md)，本轮重点：

- **撤回确认**：`/factorio-ai-assistant-mock ready` 后，回答里只有紧凑的下一步文本，**没有
  任何“加入待办”按钮**；Alerts 页没有待办区块；常驻卡片没有未完成待办行；
  `/factorio-ai-assistant-mock todos` 提示模式无效。
- **rc.4 存档升级**：用 rc.4 期间产生过待办的存档直接载入 rc.5，不弹错误、不丢聊天记录，
  已忽略的提醒仍然保持忽略。
- **§4c 自动暂停**：按钮 / `Ctrl+Shift+A` / ESC / 提醒卡片跳转的暂停与恢复语义一致；打开前
  已暂停的游戏关闭面板后必须保持暂停；关闭设置后不再暂停；多人游戏中不生效。
- **§4b 清理提醒**：`alerts-many` 后清理全部，常驻卡片消失、Alerts 全部标记“已忽略”，规则
  静音与安静模式不变；`alert-close` + `alert-reopen` 后被清理的提醒重新出现。
- 既有回归：聊天贴底 / 清空、中文显示名称、流程指南阶段判定、聊天内确定性计算、provider
  断网 35 秒降级、Companion 关闭约 10 秒转 Offline 并可恢复。

## 已知限制与实机待验

- 自动暂停**只支持单人游戏**，多人游戏中该设置不生效（UI 会说明）。
- 本 Mod 不提供任何待办 / 任务清单能力，也不与第三方 Todo-List Mod 集成；顾问仍然只读，
  不自动建造 / 研究 / 执行 Lua 或 RCON。
- 像素布局、键盘焦点、不同 UI scale 与 DPI，以及真实 Lua/UI UPS 仍需 Windows Factorio 实机
  确认。
- 本候选等待 Charles 的 Windows 实机验证，验收通过前不做 Mod Portal 发布。
