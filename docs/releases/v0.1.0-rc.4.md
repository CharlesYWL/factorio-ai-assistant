# Factorio AI Assistant v0.1.0-rc.4

第四个私有 release candidate，把 rc.3 之后的两组游戏内 UX 改进合并成一个候选：单人打开
顾问时自动暂停 + 一键清理全部提醒，以及把 AI 的“下一步建议”经玩家确认后加入本 Mod 自带的
待办列表。Mod 与 Companion 必须来自同一 rc.4 bundle 成对安装。

> **Steam 成就警告：** Factorio 启用任何 Mod 后，该存档都不能获得 Steam 成就。请先备份存档
> 并使用测试副本。

本 RC 仅用于私有 GitHub Release 和 Windows 实机验收，不发布到 Factorio Mod Portal。

## 相对 rc.3 的变化

### 打开顾问时自动暂停（仅单人）

- 新增每玩家运行时设置 **打开 AI 顾问时自动暂停**，默认开启，中英文 locale 完整。
- **该能力只在单人游戏生效。** 多人游戏共用一条 tick，Mod 绝不修改全局暂停状态，Status 页
  显示“多人游戏不可用”。
- 顶部按钮、`Ctrl+Shift+A`、`Ctrl+Shift+1..3`、提醒卡片的“打开顾问”和 mock harness 全部走
  同一条 open/close 路径，暂停语义完全一致。
- Mod 只恢复**它自己触发过**的那次暂停：打开前就已暂停、或玩家中途手动恢复后又手动暂停的
  情况都不会被覆盖；ESC / `on_gui_closed`、关闭按钮、再次 toggle、玩家离开或被删除都会清理
  claim。玩家手动恢复游戏后，周期性 handler 会因为 tick 重新推进而主动放弃 claim。

### 一键清理全部提醒

- Alerts 页和左上角常驻提醒卡片都提供 **清理全部**；没有可忽略的提醒时按钮为灰色或不出现。
- 批量忽略只写当前玩家的 `dismissed_alerts`，目标是当前 force 的活动提醒：不删除
  `state.advisor_alerts`、不改变安静模式、不改变规则静音，也不影响其它玩家或其它 force。
- 被清理的提醒在同一生命周期内不再出现；提醒关闭后再次触发会以新的生命周期重新出现。逐条
  “恢复”仍然只影响那一条。

### AI 建议 → 游戏内待办

- Chat 回答最多带 3 条结构化 `suggested_actions`，每条有确定性 `action_id`、展示文本和来源
  （`guide` / `alert` / `calculation` / `model`）。模型推断类建议必须先通过既有的
  unsafe-command、引用与数字对账校验，否则不会成为可点击建议；回答一旦回退到本地模式就没有
  模型建议。
- **待办是本 Mod 自己的功能，且必须由玩家人工采纳。** 每条建议旁的 **加入待办** 只有玩家点击
  才会写入；AI 与 Companion 无权创建、完成或删除任何待办。采纳时是从已存储的聊天记录里回读
  建议，而不是信任点击事件里的内容。
- 同一条建议无论重复点击还是在后续回答中再次出现，只会产生一条待办（按 `action_id` 去重）。
- 待办列表是 Alerts 页内的独立区块（不新增标签页）：未完成在前、按加入顺序排列，支持完成 /
  恢复、逐条删除、清理已完成、清理全部，保留来源与创建 tick，按玩家隔离并有 25 条上限；达到
  上限时拒绝新增而不是覆盖已保留的条目。
- 常驻卡片增加一行未完成待办数量，点击进入 Alerts 页，不产生任何新 toast。
- 不集成第三方 Todo List Mod，不使用 `remote.call`，不自动建造 / 研究 / 执行 Lua 或 RCON。

### 集成回归

- 新增 `scripts/lua/integration_spec.lua`，专门覆盖三组功能之间的接缝（各功能自身的用例仍留在
  `pause_spec` / `alerts_spec` / `todos_spec`）：
  - 清理全部提醒后常驻卡片因为还有未完成待办而继续存在，且不再显示提醒行和清理按钮；
  - 清理提醒不动待办，清理待办不会恢复已忽略的提醒，也不改变 `advisor_alerts`；
  - 采纳建议、清理提醒、清理待办都不会干扰或误释放自动暂停 claim；
  - ESC 关闭并恢复游戏后待办行仍在，重新打开会重新暂停；
  - `/factorio-ai-assistant-mock todos` 一次性预置提醒 + 待办，且只 claim 一次暂停；
  - 既没有待办列表也没有暂停 claim 的旧存档能安全迁移并继续正常暂停 / 恢复。

## 协议兼容

协议版本仍为 `1`，状态 schema 仍为 `2`。`assistant_response` 的 `suggested_actions` 是**可选**
字段：

- 旧 Companion + 新 Mod：回答没有结构化建议，正文照常显示，不出现“加入待办”。
- 新 Companion + 旧 Mod：未知字段被忽略，回答照常显示。
- 字段畸形或超长时整段建议被丢弃，回答正文不受影响。

`packages/protocol/fixtures/assistant-response-legacy.json` 与
`assistant-response-suggested-actions.json` 同时纳入回归，没有为了兼容而回退协议版本。

- `performance-baseline.json`：空闲、正常生产和接近 16 KiB 大基地摘要的自动基线。
- `SHA256SUMS`：上述文件的 SHA-256。
- `factorio-ai-assistant-v0.1.0-rc.4.zip` 与同目录的 `.sha256`：总包及其自校验值。

Factorio 的 Mod 版本格式不支持 prerelease 后缀，因此 Mod 内部版本仍是 `0.1.0`，GitHub 候选
标签为 `v0.1.0-rc.4`，Companion build marker 同步为 `v0.1.0-rc.4`。**不要与 rc.1 / rc.2 /
rc.3 或临时 hotfix 混装**，请成对替换。

### 可重复性边界

Mod ZIP、Companion ZIP、示例配置、`manifest.json` 和 `RELEASE_NOTES.md` 使用确定性打包，同一
提交上重复执行 `npm run package` 得到相同的 SHA-256。`performance-baseline.json` 是每次构建的
实测数据，因此它以及包含它的总 bundle 的 SHA-256 每次构建各不相同，验收时以本 Release 内的
`SHA256SUMS` 和 `.sha256` 附件为准。

## Windows 重点复测

完整清单见 [`docs/windows-smoke-test.md`](../windows-smoke-test.md)，本轮新增/重点：

- **§4d 自动暂停**：按钮 / `Ctrl+Shift+A` / ESC / 提醒卡片跳转的暂停与恢复语义一致；打开前
  已暂停的游戏关闭面板后必须保持暂停；关闭设置后不再暂停；多人游戏中不生效。
- **§4b 清理提醒**：`alerts-many` 后清理全部，常驻卡片消失、Alerts 全部标记“已忽略”，规则
  静音与安静模式不变；`alert-close` + `alert-reopen` 后被清理的提醒重新出现。
- **§4c 建议加入待办**：`ready` 模式下逐条加入、去重、完成 / 恢复 / 删除、清理已完成 /
  全部，`todos` 模式检查预置列表；**保存并重新载入存档后待办、完成状态与来源保持不变**。
- 既有回归：聊天贴底 / 清空、中文显示名称、流程指南阶段判定、聊天内确定性计算、provider
  断网 35 秒降级、Companion 关闭约 10 秒转 Offline 并可恢复。

## 已知限制与实机待验

- 自动暂停**只支持单人游戏**，多人游戏中该设置不生效（UI 会说明）。
- 待办由本 Mod 内置存储在存档中，**必须玩家逐条点击采纳**，AI 不会自动写入；不与任何第三方
  Todo List Mod 集成。
- 待办上限 25 条，达到上限时新增会被拒绝并提示，而不是覆盖旧条目。
- 像素布局、键盘焦点、不同 UI scale 与 DPI，以及真实 Lua/UI UPS 仍需 Windows Factorio 实机
  确认。
- 本候选等待 Charles 的 Windows 实机验证，验收通过前不做 Mod Portal 发布。
