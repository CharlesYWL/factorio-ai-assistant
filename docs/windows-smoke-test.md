# Windows 实机冒烟测试（20–35 分钟）

用于 `v0.1.0-rc.1` 的早晨快速验收。完整 30 分钟稳定性和 UPS 基线见
[`performance.md`](performance.md)。

> **Steam 成就警告：** 启用任何 Factorio Mod 都会让该存档不能获得 Steam 成就。
> 先备份存档，只在测试副本上执行本清单。

## 测试前（2–4 分钟）

- [ ] Windows 10/11、Node.js 22+、Factorio 2.0.59+。
- [ ] Mod ZIP 与 Companion ZIP 来自同一个 `v0.1.0-rc.1` bundle；SHA-256 与
  `SHA256SUMS` 一致。
- [ ] Steam 启动参数为 `--enable-lua-udp=34198`，修改后已完全退出并重启 Factorio。
- [ ] 解压 Companion；需要自定义时把 `companion.config.example.json` 复制为
  `companion.config.json`。不要在反馈中粘贴 API Key。
- [ ] 记录：Windows 版本、Factorio 版本、Mod 版本、Companion 版本、provider/model、
  测试存档副本名。

## 1. 连接与状态（2–3 分钟）

1. 双击 `start-companion.cmd`，确认窗口出现 `companion_listening`，地址必须是
   `127.0.0.1`。
2. 启动测试存档，按 `Ctrl+Shift+A`；Status 应在约 5 秒内显示 **Connected**。
3. 核对 Mod `0.1.0`、Companion `0.1.0`、协议 `1 / 2`，以及正确的隐私模式。

- [ ] 连接成功；没有公网监听、防火墙公网入站规则或未处理异常。
- [ ] 如显示版本/协议不匹配，停止测试并从同一 bundle 同时重装两个组件。

## 2. 聊天与降级（3–5 分钟）

1. 提问“当前最大的三个瓶颈是什么？”。
2. 回答应区分事实/推断/缺失数据，行动项不超过 3 个并带 `[A#]` 或 `[C#]` 证据。
3. 无模型时来源应为本地规则；有模型时断开 provider 网络再提问，35 秒内应返回本地
   降级答案，UI 不冻结。

- [ ] 没有 Lua、`/c`、RCON 或声称自动修改工厂的输出。
- [ ] Companion 日志没有问题全文、完整状态或密钥。

## 3. 聊天内确定性计算（3–4 分钟）

面板已不再有计算器页，全部计算由聊天触发；整节不允许输入任何 prototype ID。

1. 点“产线配比”快捷问题，或直接问“每分钟 45 个蓝瓶需要多少台机器？”。回答必须
   含 `[计算结果]` 的目标配方、精确台数、向上取整台数与假设。
2. 依次问“一分钟 120 绿板怎么配？”“每分钟 100 钢材需要多少台熔炉？”“每分钟 90
   塑料需要多少台化工厂？”“每分钟 60 硫磺需要多少台机器？”“每分钟 30 电池需要
   多少台机器？”，五问都应给出结构化确定性结果。
3. 问“每分钟 60 个电路要多少台机器？”，应得到一句列出绿 / 红 / 蓝电路的澄清。
4. 问“蓝瓶需要多少台机器？”，应得到一句要求补速率的澄清。
5. 用 `npm run calculate` CLI 以同一目标和速率复算一次，核对机器台数一致。

- [ ] 全程无需 prototype ID；歧义或缺速率返回澄清而不是猜测。
- [ ] 聊天数字与 CLI 确定性结果一致；无数据时明确报错。

## 3b. 中文显示名称（2–3 分钟）

1. 游戏语言设为简体中文，打开 Status 页确认“显示名称”一行显示 `zh-CN / <数量>`，
   数量在连接后约 5–10 秒内大于 0。
2. 问“每分钟 45 个蓝瓶需要多少台机器？”，`[计算结果]` 里的配方、机器、外部输入和
   副产物显示中文名（例如 `化学科技包`、`组装机 2 型`），ID 只作为结构化输出中的
   主键出现，不堆在正文里。
3. Chat 问“当前最大的生产瓶颈是什么？”，事实、计算和行动正文用中文名称，不应把
   `iron-plate`、`petroleum-gas` 之类 ID 直接堆在正文里。
4. Alerts 页的证据和建议同样使用中文名称。
5. 把游戏语言切换到 English 并重开面板：同样的位置改为英文名称，没有中英混排。

- [ ] zh-CN 下正文优先中文，en 下英文；未翻译或未知 ID 回退显示 ID，不报错。
- [ ] 切换语言后没有残留上一语言的名称。

## 4. 提醒与防风暴（3–6 分钟）

1. 没有可控真实条件时，先停止 Companion，在控制台运行
   `/factorio-ai-assistant-mock ready` 检查 Alerts 卡片和 toast 布局，完成后运行
   `/factorio-ai-assistant-mock clear` 并重启 Companion。
2. 有可控存档时临时调低一个规则持续门槛，制造一次缺电或断料；等待告警打开。
3. 保持条件不变至少 60 秒：同一告警不得按每个 5 秒样本重复弹出。测试后恢复设置。

- [ ] 只出现预期打开/冷却后的提醒，没有重复告警风暴。
- [ ] 静音与恢复该规则有效，Alerts 证据与当前聚合数据一致。

## 4b. 聊天滚动、清空与常驻提醒（3–5 分钟）

先停止 Companion，再依次运行以下 mock 模式（结束后运行
`/factorio-ai-assistant-mock clear` 并重启 Companion）。

1. `chat-long`：聊天区应停在最新一条。手动向上滚动到历史中部并保持不动。
2. `chat-append`：追加一条新回答后，视图应自动回到底部。
3. 再次上滚后等待任意刷新（例如 `alerts-many`），视图不得被抢回底部。
4. 点击聊天区右上角的 **清空**：历史清空并显示空状态，按钮随之变灰。
5. `loading` 后立即点击 **清空**：进行中的请求被取消，Status 页仍显示已连接。
6. `alerts-none` / `alerts-one` / `alerts-many`：左上角常驻卡片分别为不显示 / 1 条 /
   3 条，且不遮挡快捷栏、小地图与顶部按钮。
7. 在常驻卡片上忽略一条提醒：该行消失，Alerts 页对应卡片标记“已忽略”并可恢复。
8. `alert-close` 后再 `alert-reopen`：被忽略的提醒重新出现在常驻卡片中。

- [ ] 新消息 / 发送 / 完成 / 超时后聊天自动贴底；玩家上翻时不被刷新抢回。
- [ ] 清空只影响本机聊天记录，不影响 Companion 连接与提醒。
- [ ] 常驻提醒卡片状态明确、可逐条忽略，忽略与规则静音互不影响。
- [ ] 100% / 150% UI scale 和纯键盘操作下，上述按钮都可访问且不重叠。

## 5. 断网/停服降级与恢复（2–4 分钟）

1. 保持游戏运行，关闭 Companion；约 10 秒后标题应变为 Offline。
2. Chat 不再发送，且提示聊天与产线计算暂不可用；Alerts 仍可看但标记可能过期。
3. 重新运行 `start-companion.cmd`；约 5 秒内应重连并恢复同步。

- [ ] 断开和重连没有未处理异常、卡死或自动修改工厂。

## 6. 日志与失败反馈（2–4 分钟）

运行 PowerShell：

```powershell
.\collect-diagnostics.ps1
```

打开生成的 `diagnostics.zip`，确认只含 Companion 当前日志、`factorio-current.log`、
版本信息和可选的脱敏配置。分享前仍要人工检查本机路径。

失败反馈请包含：

```text
步骤：
预期：
实际：
首次失败时间：
是否可稳定复现：
Windows / Factorio / Mod / Companion 版本：
provider / model（不要提供 Key）：
Steam 启动参数：
SHA-256 是否通过：
diagnostics.zip：
截图或录屏：
```

- [ ] 通过：把清单、诊断包和版本信息交给 Charles。
- [ ] 失败：停止替换/发布，不要反复覆盖日志；按上述模板反馈。
